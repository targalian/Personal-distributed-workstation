# 任务结果未知时如何处理

适用范围：可信局域网中，任务启动响应丢失、PM 所在节点掉线，或 Secretary/Worker 重启后无法确认任务执行结果。

## 查看与核实

1. 打开工作台任务卡片，点击「查看详情」。任务已登记但执行结果未知时，会出现「结果待核实」提示及原始诊断。
2. 点击「核实原节点」。系统按数据库保存的 PM 和节点归属发起查询，返回核实时间、原节点和下一步建议。
3. 查询期间按钮禁用；连接失败后可以再次核实。切换到另一任务时，旧查询不会覆盖新详情。

核实只读取节点证据，不启动 PM、不重派任务，也不改变任务状态或验收结论。成功取得启动回执只证明曾经接受过启动，不能证明任务已经完成。

| 核实结果 | 如何处理 |
|---|---|
| 原节点 PM 仍在运行 | 等待进度或交付。需要停止时使用暂停/取消，并核对在途模型与外部工具。 |
| 原节点 PM 已停止 | 检查已保存交付、原节点日志和工具产物。停止本身不证明完成或无副作用。 |
| 有启动记录，结果待核实 | 检查原节点日志、产物及外部操作。新版任务可核实恢复条件并显式恢复原任务；不要删除回执或直接重派。 |
| 未找到启动记录 | 核对原节点和数据路径、是否恢复过旧备份。记录缺失不等于没有执行。 |
| 节点不可达 | 检查节点进程、网络与认证，恢复连接后重查。 |
| 节点版本不支持查询 | 升级原节点后重查，旧接口不会被当作执行成功。 |
| 节点/任务归属不匹配 | 核对原节点身份与地址，不采信其他节点或其他任务的运行状态。 |
| 查询期间任务变化 | 关闭详情，刷新任务后核实当前记录。 |

## 秘书重启或重新激活之后

秘书重新激活时，会将尚无交付的活动任务标记为「执行待核实」，保留原任务与PM归属。原节点可能仍在运行，不会因为秘书重启而自动重派。已保存交付、验收结论和取消/暂停意图保留。

旧版本曾把有PM归属的活动任务标为interrupted。升级后这些记录会恢复为可接收原PM回报的running状态，并显示待核实；这不表示系统重启了PM。原PM的新运行回报或合法交付会清除恢复提示。若原PM已经退出，秘书重新激活本身不创建替代执行。新版任务可另行显式申请原检查点续跑。

待核实和旧中断记录不能直接删除或快捷重提。旧标签页点击重提时会先读取当前任务；服务端在创建替代任务和绑定 PM 的事务内再次校验，避免状态变化后仍按过期缓存派发。手动新建任务前仍需核对旧执行的副作用。

## 取消与暂停的确认

取消/暂停先在 Secretary 持久化停止意图，阻止后续派发和晚到交付，再请求原节点上的指定 PM 停止后续调度。网页与聊天共用这条链路。

- 「取消/暂停已登记 · 停止待核实」表示已保存意图，但原节点尚未确认。任务详情保留诊断，提供「重发停止请求」。不要把该状态当作工具已经终止。
- 「已取消/暂停 · PM 已确认」表示对应 PM 已设置协作式停止信号。已经发出的模型调用、远端子任务或外部工具可能仍在运行，费用也可能继续产生。
- 原节点不可达或响应丢失时只发送一次 POST，再尝试一次只读回执核实。重发须由用户明确操作，沿用同一个请求编号。Secretary 重启后可读取原 PM 归属与停止意图。
- 每次控制核对节点、PM、任务、动作和请求编号；节点上已换成其他 PM 时不停止新任务。晚到暂停不能覆盖取消，晚到失败不能撤销已有确认。
- 未确认停止时禁止删除任务记录，并隐藏快捷重新提交入口。已确认后若要重新提交，仍需核对旧工具副作用与产物。
- 已有交付或完成/验收/失败终态时，取消/暂停不会覆盖现有结论。暂停当前不提供原 PM 续跑入口。

控制接口新增 `POST /role/pm-control`，请求包含 `device_id`、`pm_id`、`task_id`、`request_id` 和 `action`（cancel/pause）。旧 stop-pm/cancel-pm/pause-pm 路径保留，但同样必须携带身份；旧无参数调用返回校验错误。向旧版本节点发送新控制路径不会降级为无身份停止，应先升级原节点。

Secretary 的取消/暂停 API：HTTP 200 表示已确认（尚未派发的任务可直接确认），HTTP 202 表示意图已登记、原节点未确认，HTTP 409 表示当前任务不允许该操作。核实接口仍为只读；它不会自动改写停止确认。

控制确认保存在 Secretary 的任务库中。节点仅在原 PM 实例中保留回执，节点重启或替换 PM 后，未送达的确认可能无法恢复；此时继续保留未知结果，不假报成功。

## 已交付与后续任务

快捷重提使用 `POST /api/tasks/{task_id}/resubmit`，只允许明确失败或已确认停止的取消/中断任务。存在交付、未知执行或未确认停止时拒绝。已经派发过的任务还要求 Boss 确认在途工具已结束，并核对产物和费用；确认字段为 `acknowledge_side_effects: true`，不是系统已停止工具的证明。

每个原任务最多对应一个直接替代任务：重发请求返回同一任务，不再次启动已绑定的 PM。任务详情显示来源与替代任务，支持「查看替代任务」和「重试提交请求」。若服务器在保存后、派发前退出，重试会继续派发同一待执行任务；普通待执行队列也执行相同的原任务和预算校验。PM 启动结果未知时仍保留原 PM，不重新启动。

替代任务完整复制名称、描述、项目和 input_data（包括优先级与已确认需求快照），不复制旧输出、子任务、PM 或验收结果。原需求快照中的原始 task_id 保留，以便追溯最初下发；当前任务 ID 与来源通过独立重提记录区分。重提接口不接受改稿；修改需求应确认新版本后下发。

删除任务不会删除重提映射和原任务快照。替代任务已删除时重发返回冲突，不重新创建；原任务已删除而替代任务尚未派发时需要人工核实，不能继续派发。替代任务再次失败时，可以从该替代任务继续重提形成链条；对最初任务重发不会创建同级重复任务。备份完整任务库会保留这些记录；回退到不含新记录的旧备份仍不能撤销外部执行。

接口成功返回 `{task, duplicate, source_task_id}`，只代表已创建或找到任务，不代表执行成功。HTTP 402 为预算/项目状态不允许，409 为状态冲突、停止未确认、未确认副作用或替代任务已删除，404 为原任务及重提记录均不存在。预算校验沿用现有项目策略，不是对所有并发模型调用的费用预留或硬限额保证。

若任务已有交付，应先检查交付物和验收状态。核实操作不会覆盖验收结论。若确认需要重新工作，应在核对旧任务的工具副作用并处理重复风险后，创建新的任务；不能通过清空启动/执行回执来强制重做。

恢复备份前参见 [备份恢复说明](backup-restore.md)。旧备份可能不包含备份之后的执行记录，恢复数据不等于撤销外部操作。

## 最后保存的执行现场

新版 PM 会在执行、结果接收和交付边界保存检查点。「核实原节点」可查看最后保存的阶段及完成/执行待核实/未派发数量；写盘失败时停止后续调度并提示核实在途操作。查询不自动继续执行，旧版缺失记录不证明未执行。存储、备份与限制见 [PM 检查点说明](pm-checkpoints.md)。

## 恢复前核实步骤

任务详情的「核实恢复条件」按原执行编号读取原节点回执，区分已保存输出、待质量检查的成功回执、仍在执行、结果未知和未登记请求。查询超出时间预算可固定检查点版本继续核实；任务或检查点变化时重新开始。已有交付、停止或替代任务会提示冲突。该入口不执行恢复、不重新运行工具；完整语义见 [检查点说明](pm-checkpoints.md)。

## 当前边界

- 核实使用原任务绑定时保存的地址与端口；节点地址变化后可能无法连接，当前不自动按新地址迁移任务。
- 节点运行标志不是工具级停止证明；当前暂停/取消不保证立刻中断在途付费模型请求或外部进程。
- 只读核实不会自动续跑或强制终结任务。符合条件的新版任务可另行显式恢复原 PM；显式重提则创建独立替代任务。
- 验证覆盖真实本机 HTTP 与临时 SQLite/浏览器操作；真实多机故障与模型执行仍需单独验收。

## 接口与证据

- Secretary：`GET /api/tasks/{task_id}/execution-check`，要求 Secretary 已激活。
- Station/Worker：`GET /role/pm-starts/{pm_id}?task_id=...`，沿用现有 mesh 认证。
- 查询校验节点 ID、PM ID、任务 ID 与格式版本。远端仅一次 GET、5 秒超时、不跟随重定向。
- 启动库以 SQLite 只读模式读取；无库/无记录不创建数据库或占用执行编号。接口不返回原始回执、请求内容或进程标识。


## 恢复原任务（iter-54）

在任务详情先点击「核实恢复条件」，支持恢复时会出现「恢复原任务」。确认后沿用原任务、已完成输出与原时限；不是新建替代任务。授权及原进程排除都由服务端复核，核实成功不等于已经开始恢复。

只支持原 Linux 主机、原数据路径上的新版任务。旧版无进程锁凭据、停止/终态、无可验证继续点的澄清、过期时限、已有交付或替代任务，以及本地工具结果未知时拒绝续跑。远端在途工作按原编号继续查询，不重复执行。响应丢失可重试同一版本；若恢复后的进程再次退出，先重新核实新的检查点版本再申请。

详细顺序、接口及边界见 [PM 执行现场与检查点](pm-checkpoints.md#显式恢复原任务iter-54)。

## 等待回复的任务（iter-55）

在任务详情点击「查看待回复问题」。原 PM 已退出时先恢复原任务，再回复同一问题；原等待截止时间不会延长。支持规划前需求细化的两轮继续点及已累计回答，尚不支持任意执行阶段澄清和暂停后继续。

回复只有写入原节点检查点后才确认。网络失败时保留草稿，可重试相同问题的相同回答；即使已经进入下一题，重试也不会将旧回答写入下一题。旧草稿必须先保存并清空才能切换到新问题。PM 线程和任务详情共用该规则，旧版无问题编号调用会拒绝。详见 [执行现场说明](pm-checkpoints.md)。
