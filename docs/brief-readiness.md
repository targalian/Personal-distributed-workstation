# 待讨论队列与下发前检查

## 处理问题和未确认需求

项目描述的「待讨论」视图集中显示未确认的模块、功能和问题节点，可按待确认／已确认／全部筛选，按优先级排序。新增待讨论项会创建 `kind=discussion` 的 DAG 节点，与文档共用数据、保存、撤销及版本历史。

每项可以填写问题或需求、负责人、决策结论和验收标准。问题节点的 `decision` 记录决策结论；空白或「待讨论」「TBD」等独立占位词不能通过队列的「确认此项」。确认会修改节点状态，不会下发任务；可以撤销，也可以重新打开讨论。模块和功能的确认状态沿用已有语义，验收标准等缺项会在下发检查中单独提醒。

「在 DAG 中编辑」会选择原节点并打开字段编辑器，不为导航而修改折叠状态或布局。旧文档 `sections.questions` 中的自由文本记录完整保留并可编辑，不自动拆成问题或宣称已经解决。

决策结论同时进入 Markdown、AI 修改差异和版本历史。AI 结论仅为待采纳建议；选择结论字段不会强制采纳同一节点的其他修改。模型指令要求仅记录 Boss 已给出的结论，实际输出仍需人工审阅。

## 下发前检查

点击「确认并下发」先打开保存版本的检查页面。检查包括：

- 项目名称，以及目标、范围、需求、验收章节是否空白或仅为占位词。
- 节点是否仍待讨论／只是建议，是否缺少负责人。
- 模块/功能是否缺少验收标准，问题节点是否缺少决策结论。
- 是否有未采纳的 AI 建议，是否还有需人工复核的自由文本讨论记录。

每条提示可以定位对应章节、DAG 字段或 AI 建议。补充内容后先保存，再重新检查。检查只判断结构缺项和状态；有文字不代表内容正确、方案可行或任务已经验收。

在检查页明确点击「知悉待复核项，仍下发 vN」或「确认下发 vN」才创建任务。未保存修改、版本已变化或检查尚未加载时不能使用此按钮。服务端在实际下发时再次校验版本，并将当时的检查结果与需求内容一起保存；后续修改不改变旧下发依据。旧下发记录没有检查结果时仍可查看。

检查是产品提示，不是新的权限机制。原 API 和聊天下发保持兼容，可提交含待讨论项的已保存版本；服务端仍记录当时的检查结果。保留未决项时，使用者应结合实际任务判断能否开始执行。

## 接口与兼容

`GET /api/conversations/{conv_id}/brief/readiness` 返回 `revision`、`issues`、未确认节点/未解决问题数量和检查范围说明。它不修改文件、不调用模型、不创建任务。

`BriefNode.decision` 默认为空字符串，最长 6000 字。读取旧文档和旧建议时补默认值，不重写原文件；历史读取与恢复同样兼容。旧程序不认识这个新字段；回退应按升级说明恢复旧代码和升级前完整备份，不直接让旧代码打开已保存新字段的数据。回退前导出需要保留的新结论。

后台整理启动前现在即时查询最近任务，避免刷新后轮询尚未返回时漏掉失败/中断的费用提示；用户取消后不会创建新请求。此核实不代表能撤回供应商已在途的调用。
