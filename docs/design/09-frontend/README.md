## 项目描述编辑器

「AI 建议」视图默认不勾选变更，支持逐项选择／全选／忽略；结构变更作为整体，显示人可读节点与依赖对照。通过 `/review` 保存所选并清除建议；UI 在未保存本地修改或基准版本过期时禁用采纳。聊天 WS 通过 `brief_proposal_id` 触发刷新，即使文档还处于 v0 也能显示建议。勾选状态按会话保留于页面，建议本身由服务端持久化。

「版本历史」通过分页接口读取持久化元数据，查看某一版本时由服务端生成相对当前已保存文档的差异。恢复目标明确标为「所看版本」，需确认；存在未保存草稿、尚未查看差异或页面版本落后时禁用。恢复会创建新版本并保留页面撤销能力；请求响应按会话与加载序号校验，避免跨会话误更新。

`project-brief.js` 与 `project-brief.css` 在秘书聊天旁提供产物工作区。`ProjectBriefUI.open()` 绑定当前对话，`flush()` 在聊天前保存手工编辑，`refresh()` 同步秘书输出并保护未保存草稿。需求 DAG 支持 SVG 拖动、三层嵌套、折叠、依赖校验、缩放平移和撤销／重做；与 PM 执行 DAG 分开存储。异步加载不覆盖加载期间的新输入；保存响应即使晚于对话切换，也会更新原对话草稿的版本与同步状态。

iter-37 将历史按钮移至顶部，文档、图和预览共用 50 步历史。每个会话保存 `savedDocument` 基线，按值比较决定 dirty 状态，忽略 API 对对象字段顺序的调整；撤销不回退服务端 revision。保存及相同版本加载保留历史，显式重载／外部新版本清空历史，冲突保留历史。连续同字段输入按 1 秒窗口合并，失焦、图编辑、切换视图及保存结束分组；空操作不清空 redo。键盘事件限定在工作区内，节点属性未提交时沿用原生文本撤销。历史快照只存在页面内存中，不作为服务端版本存储。
