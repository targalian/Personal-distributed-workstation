# 项目描述后台整理

点击「从对话整理」会先保存当前草稿，再登记整理任务。模型在后台工作；文档、DAG、保存和会话切换仍可操作。完成后进入 AI 建议审阅，只有明确采纳才修改项目描述，整理本身不下发执行任务。

## 状态与操作

- **已登记／正在整理**：等待后台完成。刷新页面或重新打开会话会查询已有任务，不重新调用模型。
- **整理完成**：打开 AI 建议，比较差异并逐项采纳。正在输入时不会自动切换视图或覆盖草稿。
- **无新增建议**：本次结果与保存文档一致。
- **结果已过期**：生成期间保存了新版本，或聊天产生另一份待审阅建议。原稿和原建议保留；可「导出过期结果」作为比较材料，再决定是否重新整理。
- **整理失败／结果待核实**：模型返回无效内容、写盘失败或服务曾中断。系统不会自动重新整理；启动新请求前会即时查询服务端最近任务，再提示可能再次计费；取消不会启动新调用。停止服务不等于供应商的在途调用已经停止。
- **核实／重试整理请求**：提交响应丢失时使用。浏览器保留原请求编号与基础版本，再次点击沿用原编号。禁止同一编号改用另一个版本。

后台状态查询失败会提示并继续查询，不替换正在编辑的文档。浏览器存储不可用时，本页仍可保留请求编号；刷新后通过服务端查询最近的任务。未保存草稿仍只在当前页面内存中保留，刷新前应保存或导出。

## API 与持久化

- `POST /api/conversations/{conv_id}/brief/generation`，请求 `{request_id, expected_revision}`，返回 HTTP 202 和 `job`。
- `GET .../generation` 返回最近一次任务；可传 `?request_id=...` 查询特定请求。
- `GET .../generation/{request_id}/markdown` 下载过期候选，正文明确标记未采纳。
- 原同步 `POST .../generate` 保留兼容；新页面使用后台接口。

请求先于模型调用落盘；请求记录与最终 AI 建议在同一个 `brief.json` 原子写入。普通保存、审阅、历史恢复保留内部 `_generation_jobs` 去重记录，常规文档 API 不暴露这些内部记录。备份归档会包含任务记录；恢复后的相同请求不会再次调用模型。记录暂不自动清理，以免旧请求在重试时重新计费。

每个会话只能有一个活动整理任务，进程内最多同时运行两个。任务捕获提交时的文档和对话；后续对话不混入该次模型输入。新旧 ChatHandler 在同进程共享文档锁；后台整理使用数据目录的进程生命周期锁，拒绝第二个进程接管仍存活的整理服务。服务退出后的未完成记录转为待核实，不自动续跑。

范围仍为单个活动 Secretary、可信局域网。请求去重不代表供应商内部重试、路由降级或用户显式新建请求没有费用；旧同步接口也不具有新请求编号语义。不能将该任务锁当作整个共享文件夹的多主机写入协议。

## 验证边界

单测覆盖并发同编号重试、处理器重新创建、进程突然退出、模型错误、原稿冲突、线程创建失败、并发上限、写盘失败和离线备份恢复。Chrome 实测丢失提交响应后刷新、生成时编辑／保存／切换、草稿保护、过期结果下载和桌面／手机布局。模型输出均为测试替身，真实模型费用和跨物理主机行为仍待验收。
