评估日期：2026-10-15，第 43 轮。定位为受控试用。版本号不代表完成百分比；发布依据是验收证据。

## 建议发布范围

个人或小团队、可信局域网、1–3 台工作站，完成「讨论需求 → 审阅并确认项目描述 → PM 执行 → 交付验收」。公网、多租户、手机 App 和大规模调度不作为本次 1.0 的默认范围；若扩大范围，应先增加相应权限和部署验收。

## Loop 顺序

1. 数据闭环已具备修订历史、确认版本与任务绑定；继续以真实执行验证追溯完整性。
2. 真实任务与故障验证：优先修复验证暴露的问题，不靠扩展 UI 替代可用性验证。
3. 发布候选：可复现依赖、安装升级恢复、自动回归与持续运行。

依赖实际主机、有效模型配置和付费调用额度的验证，应明确记录环境条件和授权范围。缺少条件时标为未验证，不宣称通过。持续开发可以推进独立任务，但不得把发布检查表全部完成作为既定事实。
