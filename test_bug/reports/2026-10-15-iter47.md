# iter-47：离线备份、校验与恢复演练

原启动备份只保留主数据库，遗漏共享目录内的会话/项目描述历史，以及新增的执行/启动回执。仅恢复主库会丢失需求修订与去重依据。本轮新增完整离线备份工具和新目录恢复，不修改用户的实际运行数据。

## 完成内容

- backup_workstation.py 提供 create/verify/restore，create --plan 先列出备份路径；支持配置、主库、共享目录、用户状态目录和额外文件覆盖。
- 自动收集存在的状态、共享、主库和执行/启动回执及项目配置；排除状态目录中的旧备份、日志和运行锁。原自动主库备份保留，不视为完整备份。
- SQLite backup API 合并已提交 WAL 内容，并执行 integrity_check；普通文件使用 SHA-256、长度及目录清单校验，保存空目录和可执行属性。源变化会中止；显式主库文件同样监测 WAL，忽略仅属临时索引的 SHM。
- 归档校验核对所有成员，拒绝缺失、额外、重复、越界和符号链接；检查已提交项目描述历史文件是否存在。采用 10 GiB / 100000 文件上限。
- 恢复先校验固定归档副本，再创建全新目录，生成原路径映射；失败保留 RESTORE_INCOMPLETE，禁止覆盖现有目录。权限收紧，终端不输出凭据内容。
- docs/backup-restore.md 说明停写、配置覆盖、恢复核对、手工切换/回退及多机边界。

## 使用和边界

参见 docs/backup-restore.md。必须先停止本机及共享数据的其他写入者，再使用 --offline-confirmed。进程检查与前后摘要只是辅助保护，不是跨目录在线事务或多节点协调快照。归档无加密/签名，Windows ACL 与生产数据切换未实测。

当前恢复生成独立目录和切换说明，未自动覆盖用户主库或替换配置。模型凭据仅在被选文件中存在时保存；纯环境变量、外部工具目录及云端对象需另行保存。较早备份不包含后续执行编号或外部副作用，恢复不等于 PM 断点续跑，不能删除回执或盲目重派来消除未知结果。

后续优先完善 unknown 状态的可见诊断与原节点只读核实，使启动/掉线后的任务有明确处理入口；真实模型、多机故障、Windows 安装恢复及72小时运行继续保留在 1.0 清单。
