# iter-40：确认需求版本与任务追溯（UI-039）

此前「下发项目描述」只发送完整 Markdown，后续改稿后难以查明任务依据，重复指令也可能重复创建任务。本轮增加明确确认、固定内容快照、任务关联与查询入口。

## 完成内容

- 新增 BriefHandoff：先原子写下发准备记录和预分配任务 ID，再派发；同会话同版本只调用一次，重复请求返回既有记录。
- 记录包含文档、Markdown、版本、SHA-256、时间和任务 ID；任务 input_data._brief 保留关联，不增加数据库 schema。
- 聊天捕获请求会话及模型调用前版本，避免等待时切换会话导致错下发，或改稿后未经重新审阅下发。
- 新增 handoffs 创建/列表/详情接口；UI 确认当前保存版本，未保存禁用，旧版本返回冲突；待采纳建议不参与下发。
- 下发记录可查看内容依据、任务、PM、交付、验收结论和退回原因；内容按文本转义，任务 ID 在手机上换行。
- 任务创建失败仍保留记录；结果不明时不自动重派；最终写盘失败仍能按准备记录中的 ID 查询任务；删除任务后明确显示记录不可用。

## 验证结果

- 新增 7 项后端测试：内容固定及关联、写盘/超时失败、并发去重、会话与版本变化、真实控制器/SQLite 无 Worker 路径、接口隔离/冲突、派发后最终写盘失败。项目描述专项 36 条通过。
- 全量单测 247 passed、1 skipped；本地 loop 8/8、UI 静态 9/9；设计模块清单 91 条目一致。
- Chrome 完整回归通过；新增场景实际调用 brief/task/delivery/accept/reject 路由及 SQLite，执行端使用模拟任务。检查重复确认、原稿固定、草稿禁用、旧版本拒绝、刷新、删除任务、交付与验收、转义及会话隔离；零 pageerror。
- 桌面与手机截图已查看：project_brief_handoffs_desktop.png、project_brief_delivery_desktop.png、project_brief_handoffs_mobile.png，位于忽略的 temp_resault/。
- 真实启动器运行 Station/Worker，健康接口、首页及 Worker 信息接口均 200；TERM 后退出码 143，两个服务端口释放。

## 边界与后续

去重基于单个活跃 Secretary 的进程锁与准备记录，不承诺跨进程恰好执行一次。任务库与会话文件不是同一事务，崩溃后的 prepared/uncertain 记录需要核实；本轮不自动重试。确认快照不是防管理员篡改的审计系统，也没有新增多用户确认权限。验收操作沿用任务面板。

真实模型、跨机执行、取消/预算实测、整体备份恢复和 72 小时稳定性尚未验收。下一轮优先检查真实执行条件并推进故障与恢复闭环；不能把本轮模拟执行当作 1.0 达标证据。
