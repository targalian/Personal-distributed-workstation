# iter-54：原节点进程排除、显式恢复授权与原任务续跑

## 实现

- 新版 PM 启动前持有启动数据库旁的操作系统独占锁，保留到进程退出；检查点保存本机身份与原数据路径。恢复必须取得原锁，同进程旧 PM、活原进程、旧版无凭据和迁移现场均不能接管。
- Secretary 按任务/PM/设备及检查点版本事务登记恢复授权，复核停止、交付、替代任务和预算。同版本并发请求复用编号；保留历史授权，错误版本申请不撤销正在执行的合法实例。
- 原节点从检查点读取秘书地址，复核授权，再在 SQLite 事务中按版本更换所有者、递增版本并登记请求。重复请求不启动第二个 PM；旧所有者不能再保存。
- 恢复原 PMState 和原任务剩余时限。已接受输出复用，原始成功回报重入质量检查；远端在途工作按原设备和执行编号查询，不自动重派。新工作按原依赖调度。
- 已保存单任务返回结果、聚合结果和交付请求可继续交付，沿用原请求内容和交付时间；规划前退出可继续规划。新工具、质量检查、聚合和交付前再次检查当前业务授权。
- 网页提供固定版本的「恢复原任务」及确认、禁用、失败重试和迟到隔离。UI-047 已登记并通过 Chrome；普通只读核实仍不执行恢复。
- 无中央数据库 schema 迁移，仍为 v5。新模块 pm_lease.py、pm_resume.py、task_resume.py，设计清单 119 条目。

## 限制与下一轮

目前只支持带新版进程锁凭据的任务在原 Linux 主机、原数据路径恢复；不提供跨机迁移和 Windows 恢复。暂停/取消/失败/交付终态、待澄清、原时限耗尽、本地工具已开始但返回结果未保存均拒绝直接续跑；远端未知执行保留原编号查询。锁文件不能删除来绕过排除；PM 停止不意味着外部工具副作用已结束。

下一轮优先补待澄清恢复与暂停后继续的可靠语义，记录继续点和在途结果，保持停止意图和原时限；同时准备可重复执行的真实模型/多机故障验收。真实模型、实际多机、Windows、生产切换与 72 小时运行仍未验收，不据本轮宣布 1.0。
