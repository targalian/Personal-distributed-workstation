# iter-39：项目描述持久化版本历史（UI-038）

第 37 轮的撤销历史仅在页面内存中。本轮补服务端保存快照、历史查询、差异比较和恢复，为 1.0 的需求追溯提供基础。

## 完成内容

- 每次手工保存、AI 采纳或恢复创建独立快照；记录版本、时间、来源类型和恢复来源。
- 快照先写入独立文件，再原子发布当前文档及历史索引；主文件发布失败时旧文档和历史不变，未提交快照不能从 API 读取。
- 旧数据从升级时最新版本开始保留，不声称可找回升级前未记录的版本。
- 新增每页 50 条的历史接口、指定版本文档与差异接口、带 expected_revision 的恢复接口。
- Web 新增「版本历史」：查看 Markdown、当前与旧内容对照、恢复为新版本。未保存草稿时禁用恢复，并发新版本由服务端阻止覆盖。
- 将用户询问的 1.0 差距与验收门槛写入 `docs/1.0-readiness.md`，后续 loop 转向需求—任务追溯和真实使用验证。

- 新增 5 项后端测试：持久化恢复、旧文件迁移、主文件发布失败、建议与历史边界／分页、API 比较恢复与隔离。专项 29 项通过。
- 全量单测 240 passed、1 skipped；本地 loop 8/8，UI 静态 9/9，文档清单 90 条目一致。
- 完整 Chrome 集成回归通过，新增版本比较、恢复、未保存草稿保护、并发保存拒绝、刷新后历史仍在、桌面／手机布局；零页面脚本错误。
- 真实 Station 健康接口／首页和 Worker 信息接口 200，TERM 后两项服务端口释放。
- 截图已查看：`temp_resault/project_brief_revisions_desktop.png`、`project_brief_revisions_mobile.png`（不入库）。

## 边界

采用单个活跃 Secretary 的进程锁。历史来源是操作类型，不是多用户身份。历史暂不自动清理，写入中断可能留下未索引的快照准备文件；备份必须覆盖整个会话目录。恢复后待审阅 AI 建议可能过期，需要重新整理。尚未完成真实模型／多机端到端、整体备份恢复和长期稳定性验收。
