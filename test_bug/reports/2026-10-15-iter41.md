# iter-41：交付失败不能误报项目完成

检查 1.0 执行链路时发现四条假成功路径：聚合异常被包装成文字并交付；交付 HTTP 失败仍报告完成；子任务进度以 PM 身份提前结束父任务；交付接口对不存在任务仍返回成功。本轮修复这些结果边界。

## 改动

- 聚合拒绝模型错误标记、异常和空内容，报告失败并保留子任务输出。
- 单任务和聚合路径只有在 HTTP 200、ok 为 true、任务 ID 匹配后报告完成。交付前尝试保存本地文件；未获确认时不记录成功任务记忆。
- 子任务进度以 member 身份上报；整体进度在聚合与交付完成前保持 in_progress。
- 交付接口拒绝不存在任务、已绑定到其他 PM 的任务和空产物；落库成功后才确认。兼容内嵌 PM 启动时尚未绑定 PM ID 的窗口。

## 验证

- 新增 24 条测试，使用真实 FastAPI 路由及临时 SQLite，模型和网络故障由测试注入。
- 覆盖错误模型输出、空文本、异常、HTTP 503、无效 JSON、错误任务 ID、否定回执、超时、写盘失败、服务端已保存但回执丢失，以及单任务/聚合成功、交付后验收和子任务进度不影响父任务。
- 全量 271 passed、1 skipped，本地 loop 8/8，UI 静态 9/9，文档清单 92 条目一致。
- Chrome 完整工作区回归通过，包括上一轮下发、真实交付/验收接口与手机布局；执行端仍是模拟任务。
- pre-push 无阻断错误，既有风格警告保留。本轮没有重复运行启动冒烟；上轮启动证据继续保留，但不计作本轮新验证。

本机模型池有 16 项模型配置，未发现内联或当前环境凭据，项目及用户数据目录无 .env；未执行真实模型调用。

回执超时仍可能发生在服务端保存之后，当前显示失败并要求核实交付记录；没有自动重派。文件写入仍是尽力保存，尚无可靠交付队列。监控生命周期、取消后晚到结果、交付重试覆盖验收、多机故障恢复是接下来的优先项。本轮验证不证明端到端可靠执行或 1.0 已达标。
