# iter-59：迁移前快照、schema 事务回滚与恢复后启动

## 问题和实现

主库此前在 schema 初始化完成后才做日常备份；初始化有两处 executescript 隐式提交，逐版本更新也自行提交，部分 SQL 错误被忽略。升级失败可能留下部分结构和不足以回退的备份。

- 初始化以 `BEGIN IMMEDIATE` 排除并发写入，先验证版本；未来版本、非法版本与缺失迁移必须失败。
- `schema_upgrade.py` 在任何 schema 写入前，用独立只读连接和 SQLite backup API 保存已提交页面，包括 WAL 内容。快照先写 `.pending`，通过 integrity_check、文件 fsync 后用独占硬链接发布 `.sqlite3` 并同步目录；崩溃前未发布的文件不能当正式快照。
- 文件名包含原路径摘要和源/目标版本，权限 600，位于数据目录 `backups/upgrades/`；不被日常三份备份清理。备份失败拒绝迁移。
- 基础建表、所有待应用迁移、版本写入使用同一事务；不再使用 executescript 的隐式提交。已有列按实际结构跳过，其他 SQL 错误向上传递。失败回滚并关闭连接，提交成功后才记录版本完成。
- schema 仍为 v5，没有新增业务表或 API。补充升级/恢复说明，设计映射共 133 项。
