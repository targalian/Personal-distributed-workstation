# iter-38：AI 项目描述差异审阅（UI-037）

秘书聊天和「从对话整理」改为产生待审阅建议。用户比较差异并选择采纳后才修改已保存文档，避免模型直接覆盖手工内容。

## 实现

- 新增 `brief_review.py`：项目名称、章节及节点属性逐项比较；节点集合、顺序、包含关系或依赖改变时合并为整体结构项，防止部分采纳导致断链。
- 待审阅建议与已保存文档在同一 JSON 内原子持久化，包含建议 ID、基准版本、时间、候选文档及差异。重启、刷新、会话切换后可继续审阅；每会话保留一份建议。
- 新增 `/brief/review`：所选修改经完整文档校验后一次保存；空选择忽略全部，文档版本不变。版本和建议 ID 双校验，阻止并发审阅和旧建议覆盖新编辑。
- 文档 API 附带 proposal；generate 不再自动更新文档。聊天结果通过 brief_proposal_id 通知页面。Markdown 与 PM 下发仅使用已保存内容。
- 新增 AI 建议视图，默认无选择、左右差异比较、全选／清空／保存所选／忽略全部。结构项使用人可读节点与依赖展示；小屏切换纵向对照。
- 未保存本地草稿时禁用采纳，忽略建议保留草稿；采纳可在本地撤销，旧版本建议只能忽略后重新整理。

## 边界和下一轮

结构变化整体采纳；暂不支持结构内逐节点合并。拒绝后不保存建议历史；手工编辑形成新版本后不自动合并旧建议。下一轮补持久化修订历史和版本比较，再完善确认版本及 PM 下发追溯。
