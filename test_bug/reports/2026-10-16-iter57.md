# iter-57：暂停后显式继续与执行代隔离

## 实现

任务详情在核实暂停现场后提供「继续暂停任务」，继续复用原任务、原执行编号、保存结果、澄清上下文和原截止时间。暂停时间不补偿；未知本地执行不重做，远端在途执行继续查询原编号。

- `task_continue.py` 在任务事务内登记绑定原暂停请求/检查点版本的继续请求，重复操作复用请求。准备期间保持暂停；原节点接管后才激活，归档原停止记录，设置执行代号并撤销旧恢复授权。取消、交付、替代任务、归属或预算变化拒绝授权。
- `pm_activity.py` 计数主执行、调度、进度、质量回调及回复活动，核实同路径/PM 的所有存活对象及主/进度线程，包含已离开 current 指针的旧对象。旧活动未退出时拒绝继续，退出后封闭旧实例；不清除旧实例 stop_event。
- `pm_continue.py` 保留原 Linux 主机原路径的 OS 进程生命周期锁，按版本原子替换检查点 owner。先持久化 prepared，再由秘书激活；新实例线程等待闸门，launched 落盘后才放行。准备后崩溃、激活确认丢失、线程创建失败和启动落盘失败可重试；已启动请求不重复启动，进程退出后走普通恢复。
- 新快照增加 generation/continuation，无中央 schema 迁移。停止请求与回执绑定执行代；数据库在状态/进度/子任务/交付写入事务内核对代号，旧全任务写入不能恢复已消费的暂停。第二次暂停丢失确认仍可从磁盘核实。
- 复用暂停保存的规划、直接执行、子任务和聚合返回；原始回报仍经质量与有界失败处理，未知回报明确失败。修复状态恢复替换 set 导致监控器引用旧重试集合的问题，避免最终本地接管失败后额外重试。
- UI-049：继续确认、等待在途结果、失败重试、重复点击、切换任务迟到隔离；成功刷新任务详情，刷新失败明确区分「已确认继续」与「继续未获确认」。输出区隐藏内部控制记录，交付单独展示；桌面和手机 Chrome 均验证。
- 设计映射新增 4 项，共 127 条目；同步任务恢复、检查点、1.0 门槛及对应设计域。
