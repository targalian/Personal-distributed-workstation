# iter-61：项目描述后台整理与持久化状态

## 实现

- 新增 `BriefGeneration` 和后台生成/查询/过期候选 Markdown API。提交捕获文档与对话；先持久化请求，再调用模型。重复编号返回原任务，不能更换版本；每会话一个活动任务、进程最多两个。
- 同进程 BriefStore 共享锁；数据目录持有进程生命周期锁，拒绝其他仍存活进程接管。新 ChatHandler 查询同一正在运行任务；进程退出或终态写盘失败后仅标记待核实，不自动重发模型调用。
- 任务完成与 AI 建议同一原子提交。人工新版本、另一份聊天建议或删除会话均不被晚到结果覆盖；冲突候选保留并可下载，仍需用户明确审阅后采纳。
- 前端保存/登记后解除工作区锁定；后台状态独立展示，生成时可继续编辑、保存、切换。提交响应丢失后保留请求编号与版本，刷新查询服务端原任务；写操作序号与会话加载序号共同拒绝晚到状态/建议。
- 生成期间输入或主动切换视图不自动跳转审阅，后台 GET 只合并建议元数据，不替换草稿/撤销历史。失败/中断后开始新请求提示可能再次计费。旧同步 API 保持兼容。
- 普通保存、历史恢复、审阅保留去重记录；离线备份恢复同样保留请求身份。新增使用说明 `docs/brief-generation.md`，设计映射共 137 条。
