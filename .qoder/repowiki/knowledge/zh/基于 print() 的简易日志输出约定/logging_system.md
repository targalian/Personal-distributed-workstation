本仓库未引入任何第三方日志框架（如 logging、structlog、loguru），也未定义统一的 logger 实例或日志级别配置。所有运行时信息输出均通过 Python 内置 `print()` 完成，并遵循一个简单的前缀约定：以 `[模块名]` 作为行首标签，便于在控制台快速过滤和定位来源。

**已观察到的模式与约定**
- 前缀格式：`[Station]`、`[Secretary]`、`[BotGateway]`、`[AgentRuntime]`、`[ModelRouter]` 等，对应所在模块/组件名称。
- 启动阶段集中打印关键运行参数（设备 ID、共享目录、数据库路径、端口、Web UI 地址）。
- 异常路径使用 `print(f"...异常: {e}")` 形式记录错误上下文，部分位置附带 `[WARNING]` 标记。
- Uvicorn 的日志级别被显式设为 `warning`，仅保留 FastAPI/ASGI 层的严重告警，避免与业务 `print` 混在一起。
- 代码审查指南 (`CODE_REVIEW_GUIDE.md`) 将「是否使用 `print(f"[模块名] ...")`」列为必查项，说明该约定已被纳入团队规范。

**架构影响**
- 无结构化字段、无日志级别、无文件/远程 sink，无法按环境切换输出目标。
- 所有输出走标准输出，需依赖外部进程管理器（systemd、Docker stdout）进行收集。
- 由于缺少统一 logger，新增模块时难以保证输出风格一致，目前主要靠人工约定约束。

**开发者应遵循的规则**
1. 使用 `print(f"[{模块名}] 描述信息: {变量值}")` 输出业务日志，保持 `[模块名]` 前缀。
2. 错误路径优先包含异常对象 `e`，必要时加 `[WARNING]` 前缀区分警告与正常流程。
3. 不要在循环中高频打印，避免刷屏；对周期性事件可考虑节流或仅在首次/异常时输出。
4. 如需持久化或分级日志，应在应用入口统一接入日志框架后再替换现有 `print` 调用。
