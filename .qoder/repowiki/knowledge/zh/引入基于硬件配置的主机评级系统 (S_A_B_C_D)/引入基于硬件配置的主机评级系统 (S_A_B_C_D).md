# 引入基于硬件配置的主机评级系统 (S/A/B/C/D)

_来源：c07750f → e83d993 提交周期内记录的编码计划——内容为规划时意图，实现可能滞后或有出入。_

**状态：** accepted

## 背景
系统需要一种机制来量化和分类局域网内不同性能的工作站，以便后续的任务调度或资源分配能依据主机能力进行决策，而非仅依赖在线状态。

## 决策驱动
- 资源可视化的标准化
- 为智能调度提供数据基础
- 算法简单性与可解释性

## 备选方案
- **无评级，仅记录原始硬件参数** _（已否决）_ — 优点：数据最原始，无信息丢失；缺点：用户和调度器难以快速判断主机相对性能，缺乏直观的等级概念
- **基于实时负载的动态评分** _（已否决）_ — 优点：反映当前可用性；缺点：波动大，不适合作为主机固有能力的标识，计算开销大
- **基于静态硬件配置 (CPU/内存/磁盘) 的加权评分与分级** — 优点：稳定反映主机潜力，计算轻量，S/A/B/C/D 等级直观易懂；缺点：无法反映实时负载情况，需配合心跳监控使用

## 决策
实现 `lan_mesh/host_rating.py`，采用加权算法对 CPU 核数、内存、磁盘进行打分（满分 100），并映射为 S/A/B/C/D 五个等级。评级结果存入 `hosts` 表，并在主机注册或配置变更时重新计算。

## 影响
数据库 `hosts` 表新增 `rating_tier`, `rating_score`, `rating_summary` 字段。API 和 UI 需展示这些评级信息。调度模块未来可调用 `get_hosts_by_tier` 筛选合适的主机。
